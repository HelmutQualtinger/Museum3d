# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

A walkable 3D art museum rendered entirely client-side with Three.js. The whole app — markup, styles, and logic — lives in a single file: `index.html`. There is no build step, no package.json, and no bundler; Three.js is loaded from a CDN via an import map.

## Architecture (all in `index.html`)

- **Data**: `ROOMS` array defines six galleries on a grid: `cell: [col, row]` places each hall at `x = col·ROOM_W`, `z = row·ROOM_D`. Row 0 is the original enfilade (I Porträt, II Landschaft, III Moderne); IV Skulptur sits behind hall II (`[1, 1]`), V Gauguin in front of it (`[1, -1]`), VI Höhlenmalerei in front of that (`[1, -2]`, entered through its back wall). Wherever two cells touch, a doorway appears automatically (`roomAt` lookups in `buildRoom`). Each hall lists its paintings per wall: `back` (z = ROOM_D) and `front` (z = 0) hold three, or only two when the wall has a doorway (a third is dropped silently); `left`/`right` hang two on a *closed* side wall (the former head-wall paintings now live in `ROOMS[0].left` and `ROOMS[2].right`). `DIVIDER_PAINTINGS` (keyed by the divider's world x, 16 or 32 — dividers only exist in row 0) hangs one painting per wall segment and side, `face: 1`/`-1` picking which of the two adjoining rooms it faces; Monet's *Impression* moved onto the back of the Whistler segment when hall II's back wall got its doorway. `bench` is optional — halls IV and VI have none because `SCULPTURES` stand in their middle, hall II none because of the spiral stair (`stair: true`); in hall I the two Egyptian pieces (3× enlarged, no vitrine) flank the bench. Benches are **not** colliders: `onBench` raises the eye height by `BENCH_H` while you stand on one (smoothed in the walk loop, and in `travelTo`'s target), so you step over them. Total: 52 pictures (49 paintings/photos + a live-rendered Mandelbrot spiral + the self-building spray portrait *Maria* + the *LichtOrgel* web app) plus 10 sculptures (including the copper vase and the pierced gold cube in hall III, the Venus de Milo and Rodin's Thinker on the roof and the gold Osiris in Mykerinos' chamber); keep the meta description tags, the `og:`/`twitter:` variants, and the `Sammlung:` comment above `ROOMS` in sync if that changes. `roomIndexAt(x, z)` maps a world point to its hall (−1 outside).
- **Artwork URLs**: 1280px Commons thumbnails, not originals. Several originals are enormous (Starry Night is 44567×35291) and fifteen full-size textures would run to gigabytes of GPU memory. The data keeps the 1280px URLs, but `sizedUrl` rewrites the width when loading: every painting loads at 500px at startup (≈1.7 MB total instead of ≈11 MB), and only the painting in focus mode gets a 1920px texture (`showHiRes` in `enterFocus`). At most one high-res texture exists at a time; `dropHiRes` swaps back and disposes it once the exit animation finishes, not when it starts, so the picture doesn't visibly blur while the camera is still close. Only Commons' standard thumbnail widths (…, 500, 960, 1280, 1920, 3840) are safe to request; others return HTTP 400. When adding a work, get the URL and true `ratio` (height÷width) from the Commons API rather than guessing — and check `DateTimeOriginal`, since file titles often omit or misstate the year.
- **Scene setup**: standard Three.js scene/camera boilerplate, ACES tone mapping, fog for depth. The field of view is capped at 68° vertical *and* 80° horizontal (`applyFov`, also on resize): a fixed 68° vertical gave ~95° horizontally on a 16:10 window, and the edge stretch made the square marble tiles visibly grow and shrink while turning. The renderer is `WebGPURenderer` (import map points `three` at `three.webgpu.js`, r172), which falls back to its WebGL 2 backend on its own when `navigator.gpu` is missing — no separate code path. Its materials are converted to node materials internally; `onBeforeCompile`/`ShaderMaterial` tricks from the WebGL renderer won't work. Only the terrace sun casts shadows (`buildRoofTerrace`); `renderer.shadowMap` is on for that alone.
- **No stalls on the stair, frame rate on the roof** (measured: a 1–1.5 s freeze crossing `ROOF_SEEN`, 11 fps by the Venus):
  - **Lights never change visibility.** WebGPU keys every render object on the scene's list of visible lights. When the sun and sky light hung in `roofGroup`, toggling the roof rebuilt all ~900 render objects on every trip up or down. Sun, its target and the hemisphere light therefore sit directly in `scene` (sun and target positioned in world coordinates). `setIndoorVisible` hides only the *meshes* of the halls (`indoorRoots`) once you are outside, more than 12 m from the stair, never their lights.
  - **Anything under `roofGroup` gets daylight only.** `assignRoomLights` gives every mesh under `roofGroup` only `UPPER_ROOM`'s lights, whatever its bounding box. The bushes reached 1 cm below `ROOM_H` and so computed the lights of every hall below them, which cut the frame rate to a fifth. Keep roof objects above `ROOM_H` anyway (bushes, Eiffel legs).
  - **Warm-up.** `warmUp` (on `loadingManager.onLoad`, behind the start overlay) runs `compileAsync` and one render with the roof visible and `frustumCulled` off everywhere, so pipelines, shadow-pass pipelines and texture uploads happen there.
  - **Indoor animations stop above `ROOF_SEEN`.** Turntables, the spray portrait and Mandelbrot colour cycling only run below it: from the roof the halls lie inside the view frustum but can't be seen.
  - **Manual shadow updates.** The sun's shadow map has `autoUpdate = false`. `needsUpdate` is set when the snapped shadow centre or its size changes, or while the centre is within 45 m of the terrace, where the palms sway.
- **Render on demand**: the scene is static, so the `setAnimationLoop` callback only calls `renderer.render` when the camera's world matrix changed or `needsRender` is set (texture loaded, resize, tab visible again). After any such change it keeps rendering for `SETTLE_FRAMES` (30) more frames, because a single frame after closing the start overlay sometimes stayed black. Resolution is capped by `MAX_PIXELS` (2.2 MP) in `applyRenderSize`, not just by `devicePixelRatio ≤ 2`: each pixel evaluates every light its hall sees, and a full-screen Retina Mac otherwise renders 4–5 MP versus ~1 MP on a phone — that's why the Mac ran slower than phones. Anything that changes the scene without moving the camera — e.g. a material change on hover — must set `needsRender = true` or it won't show until the next camera move.
- **Floor**: `makeMarbleFloorTexture` computes polished marble slabs pixel by pixel onto a 1024² canvas once at startup (~0.6 s on a Mac, behind the loading screen): 4 × 4 slabs of `MARBLE_SLAB_M` = 1 m per tile, a checkerboard of light Carrara and slightly greyer stone, each slab with its own value-noise turbulence driving a distorted sine for the veins (sharp core plus soft halo, so they don't read as cracks) and finer secondary veins. Because every slab has its own seed and the joints separate them, the noise never needs to tile — only the joint lines are split half/half across the tile edge. The floors get **world-space UVs** (`floorGeometry`: u = x / 4 m, v = −z / 4 m, no `texture.repeat`), so the pattern runs on seamlessly across all halls. Per-room UVs restarted the tile at each room's edge; halls IV and V (14 m = 3.5 tiles off hall II) were then shifted by half a tile, same-coloured slabs met at the doorway and read as double-size when crossing. `roughness: 0.28` lets the ceiling lights show as gloss on the floor. Each room's `floor` value is a near-white *tint* multiplied over the texture, not a solid color — dark values there would cancel the marble out.
- **Room construction** (`buildRoom`): builds floor, ceiling with light panels, front/back walls (two-tone: accent lower band, light upper band), side walls, and a genre sign above the entrance — on the front wall, except in halls behind the enfilade (row > 0), where it hangs on the back wall so it faces you as you enter. Front/back walls are single-sided planes, and each hall builds its own side of a shared one; with a doorway, `buildSolidWall` splits each band into pieces left and right of the opening plus one above `DOOR_H`. Jambs, lintel trim and colliders of a shared front/back wall are built only by the hall in front (via its back wall), mirroring the divider rule below.
- **Dividing walls** (`buildSideWall`): outer sides are a single plane; between two halls it builds a solid wall with a wide opening (`DOOR_W` × `DOOR_H`) — two box segments either side, a header above, and dark trim jambs. Boxes, not planes, because the wall is seen from both rooms. **The divider is built only by the left of the two halls** (`xLocal === ROOM_W`); both neighbours otherwise place identical geometry at the same world x, giving z-fighting and doubled colliders. `placePaintingOnSideWall` hangs paintings on these X-normal walls (`left`/`right` in `ROOMS`, and `DIVIDER_PAINTINGS`) — it's the X-axis counterpart to `placePainting`'s Z-normal logic, rotating the frame ±90° instead of 0°/180°. The standoff from the wall differs by geometry: `WALL_T + 0.02` off a flat plane (head wall, matching the front/back wall convention) vs. `WALL_T / 2 + 0.02` off a divider box's actual surface (half its own thickness, not the full plane convention — using the plane offset there would float the frame visibly off the box).
- **Painting construction** (`buildPainting`): fits each painting's texture into a bounding box preserving aspect ratio, adds a frame, a placard (rendered to a canvas texture), and two spotlights.
- **Painting lighting** — deliberately tuned, don't undo it casually: the canvas material is near-matte (`roughness: 0.98`) and carries the texture as an `emissiveMap` at `emissiveIntensity: 0.45`, so the artwork shows its true colors independent of the lights. Spots are narrow (32°) and dim (13) rather than floodlights. The earlier glossy material under a 42-intensity, 54° spot put a specular sheen over every painting and a white halo on the wall. Room brightness comes from the ceiling `PointLight`s, not the picture lights — raise those if a hall looks too dark, not the spots.
- **Light budget**: exactly **one** spot per painting, plus one per sculpture. The renderer is forward, so every light is evaluated per fragment. Scene total is 49 + 4 spots + 18 points + hemisphere + directional, but **no material sees all of them**: `assignRoomLights(root)` gives every `MeshStandardMaterial` under `root` a `lightsNode` (TSL `lights([...])`) with only the spot/point lights of the hall(s) its world bounding box touches (`roomsTouching`, both axes), plus hemisphere and directional. A hall's surfaces see roughly 10–14 lights; dividers, jambs and the shared front/back wall planes (which sit exactly on the boundary) see both halls. Shared materials get cloned once per hall set, each with its own `customProgramCacheKey`, because the renderer's shader cache treats every object-valued material property as `{}`. It runs once over the scene after building, and again on each sculpture model when its GLB arrives; anything else added later falls back to all lights. Mind this budget before adding more paintings, especially on mobile.
- **Mandelbrot spiral** (`makeMandelbrotTexture`, `updateMandelbrot`): a painting def with `procedural` instead of `url` gets that function's texture instead of a Commons image. The Mandelbrot one is a render target that a TSL `QuadMesh` fills with the fractal; the canvas itself is an ordinary painting material, so lighting matches the others. Deep zoom uses **perturbation theory**: `computeReference` iterates one reference orbit Z_n on the CPU in BigInt fixed point (`MANDEL_FP` = 160 fractional bits) and uploads it as a float `DataTexture` (`refTex`); the shader iterates only δ' = 2Zδ + δ² + δc in float32 and rebases (δ ← Z+δ, m ← 0) whenever |Z+δ| < |δ| or the reference ends, so one reference serves the whole view. The derivative is tracked per image width (`dzw`), not per unit c, or it overflows float32 deep down. The view (`mandel.cx/cy` as BigInt, `mandel.span`) changes only in the close-up: for a `fractal` hotspot the zoom is split: up to `MANDEL_ZOOM_MAX` it is the fractal's (`mandelSpanFor`: 0 = the starting spiral, down to `MANDEL_ZOOM_MIN` = span 1e‑26 where δ would underflow, up to `MANDEL_SPAN_MAX` = 4, the whole set), and only beyond that does the camera back off towards the placard (`focusPose` subtracts `MANDEL_ZOOM_MAX`, `zoomMaxFor` = that + 1). Dragging shifts the fractal whenever the camera is still at the painting; wheel/pinch keep the point under the cursor, dragging shifts the centre (`shiftMandelView`). Shift deltas go through `f2b`, which keeps the mantissa — a plain scale-and-round would lose them deep in the zoom. Each change renders a 640 px preview (`mandelLo`, ≤ `MANDEL_MAXIT_LO`); after `MANDEL_SETTLE_MS` the 1600 px version renders in `MANDEL_STRIPS` scissored strips, one per frame, with `autoClear` off after the first (a clear would wipe the whole target), so a 20 000-iteration pass can't stall the GPU long enough for a device reset. The last strip's scissor must stay inside the target or WebGPU drops it. Iterations grow with depth (`mandelIterations`, cap 20 000); areas needing more stay black. The view is **kept** after leaving the close-up — the wall shows it, and re-entering continues there (`mandel.zoom` holds the fractal part of the zoom); `saveMandelView` stores centre (BigInt as string) and zoom in `localStorage` (`mandelbrot`) on `exitFocus`, `openMenu` and `pagehide`, `loadMandelView` restores it at startup. Above `MANDEL_DIRECT_SPAN` (0.01) `prepareMandelView` uses the origin as reference (its orbit stays 0, so δ is simply z): an escaped reference near the centre grows to thousands, and cancellation in 2Zδ + δ² then let interior points escape. WGSL has no integer `mod()` in TSL r172 — the texel index is computed by hand. **Colour cycling**: the expensive pass writes only data (palette position `t`, relief, and sharpness mapped to 0.5…1 with 0 marking the inside — a −1 for inside arrived as 0 in the target, so the interior took a cycling palette colour) into nearest-filtered `mandelDataLo/Hi`; a cheap second quad (`makeMandelColorQuad`, `colorizeMandel`) turns that into colour in `mandelLo/Hi` with the palette offset `uHue`, one full turn per `MANDEL_CYCLE_SECS` (30 s). `cycleMandelColors` recolours every frame — and so forces a render — only while the canvas is in the frustum (reusing `_frustum` from `updateTurntables`, which therefore runs first), like the turntables.
- **Web app on the wall** (`web`, `updateWebFrame`, `webFrame`): a painting def with `web` (the *LichtOrgel*, repo `../Lichtorgel`, on the rear segment of the hall II/III divider facing hall II) starts with its `og-image.jpg` as an ordinary painting (`userData.url` is null, so no hi-res). `web` is the **relative** URL `../LichtOrgel/?embed`, because the wall texture needs the iframe to be same-origin (GitHub Pages, or locally one server over both folders — serving only `Museum3d/` leaves the static image). Within `WEB_NEAR` (30 m) on the ground floor the page loads into the fixed `<iframe id="webFrame">` (`allow` microphone, display-capture, autoplay, fullscreen), which lies invisible behind the 3D canvas (`opacity 0`, `z-index −1`). Its `?embed` mode exposes `window.lichtorgelEmbed` (`muted`, `paused`, `capture`, `canvas`, `setMuted`): while the canvas is in `_frustum` (`updateWebFrame` runs after `updateTurntables`), `capture` makes it composite every frame with its theme background into the 768×403 `embed.canvas` — WebGL/WebGPU canvases can only be read in the task that drew them — and the museum copies that at `WEB_FPS` (30) into a `CanvasTexture` on the painting (it then also becomes `loTex`). Out of view `paused` stops its rendering. It is muted (its own speaker gain after the analyser, speech suppressed) except in the close-up: there the iframe lies exactly over the canvas (`webFrameRect` projects the four corners), only while the camera stands still, is clickable and audible, and the jazz is ducked. Zoom is limited to 0…1 (`zoomMinFor`). Esc inside the iframe also exits.
- **Spray portrait** (`makeSprayTexture`, `drawSpray`, `updateSpray`): a painting def with `spray` and `photo` (hall I, rear segment of the divider, facing hall I) gets a `CanvasTexture` that shows the photo for `SPRAY_PHOTO` s, then replays the four stencils in `bilder/maria-s1…4.png` — plate on, paint sweeps top to bottom, plate off, light to dark, then `SPRAY_HOLD` s on the finished picture. The PNGs are one flat colour with the stencil opening as alpha, 720×900, taken from `DATA.masks` of the published page in the user's `Schablone` repo; `bilder/maria-foto.jpg` is that page's `DATA.photo`, aligned with the masks. Use only this retouched version: the original `quelle/Maria.png` is kept out of that repo and still shows a name label. Like the turntables it advances only while in the frustum; uploads are limited to `SPRAY_FPS`, and nothing is drawn while the photo or the finished picture stands still. It has no `url`, so `showHiRes` skips it.
- **Spiral stair and roof terrace** (`buildStair`, `buildRoofTerrace`, `stairAt`, `stepStair`): hall II's centre holds a stair of 40 instanced wedge treads, 2.5 turns round a post, through a round opening (`slabWithWell`, `WELL_R`) in the hall's ceiling; the middle ceiling panel is left out there (its point light stays). `UPPER_Y` is the terrace's height; the terrace isn't an entry in `ROOMS`. The visitor doesn't walk the stair freely: `stairAt(u)` is a fixed path in running metres — straight run-in at the bottom, helix, straight run-out over the platform at the top — and `stair` holds `level` (0/1), `active`, `u`. Walking into the mouth (`atStairMouth`) or clicking the stair (`stairClicked`, invisible `stairProxy`, also an occluder) puts you on it; a click walks there first and then climbs by itself (`auto`), which is the only way up on phones, since touch has no forward key. On the path W/S/wheel go in the view direction and yaw turns with the helix, or you'd soon face the post and forward would flip to backward; a click (re)starts the automatic climb, never pauses it — W/S take over and stop it. Elsewhere `stairBlockR` keeps you out of a circle round the stair. On level 1 `resolveCollision`/`isBlocked` use `roofColliders` instead of `colliders` and clamp to a circle of `LAND_R` (190 m) round the terrace centre (`ROOF_CX/CZ`), so you can walk out into the landscape; only sculptures are clickable from up there (the lawn is an occluder), and `raycastFloorAt` rejects the other storey's floor seen through the opening.
- **Landscape and villa**: from outside, the museum is a Roman villa. The terrace is its peristyle garden: west and east wings (8 m deep, stucco over a Pompeian-red base, hip roofs of imbrex/tegula tiles from canvas textures, garden doors and small high windows), a double colonnade with a pitched roof on the north and south sides (the way out), and a pedimented portico with a cypress avenue on the west. Gravel paths lead to the monuments, holm oaks stand in the meadow. Everything is merged per material. The landscape disc (`LAND_DISC` 440 m) is a lit `MeshStandardMaterial` (fine grass tiled in metres, large meadow tones as an `emissiveMap` on `uv1`/`channel = 1`) and is a floor mesh, as are paths, ground patches and colonnade paving. `solid()` adds a roof collider and, with a height, an invisible box in `landBlockers`: a click on a monument walks to its foot instead of hitting the ground behind it. Out there `findPath` builds its grid only over start, goal and a margin, coarse enough for ≤ 90 000 cells; `travelTo` turns walks over 12 m into a stroll (`focusState.stroll`, ~9 m/s, view in the walking direction), which a new click or a movement key cancels (`stopStroll`). While the eye is up there, the sky dome, sun sprite and sun light follow the camera (the shadow centre snaps to a 4 m grid), the fog turns to horizon haze `0xe6eef0`, and `camera.far` grows to 460. The room label reads „Landschaft“ outside the terrace. Chichén Itzá (El Castillo) has nine terraces with leaning walls; pilasters divide them into recessed panels (the wall material is darker), and a cornice slab tops each one. Four stairways of 91 steps each run between balustrades, and two serpent heads sit at the foot of the stair facing the visitor. The temple on top has a base moulding, three openings between serpent columns at the front and one on each other side, a dark interior, a medial moulding, a frieze with step-fret texture, a crowning cornice and battlements. `TOP` is derived from the outer edge of the top cornice, so the stairs, which climb more gently than the terraces, run in front of every terrace and meet the platform exactly. The parts are merged per material (`M`). The temple has doors on all sides; the front has one wide opening that two serpent columns divide into three. Inside, on a dark sapodilla-beam ceiling, stands **Montezuma's feather headdress** (Penacho, Weltmuseum Vienna) in a vitrine in the middle of the room, facing the main entrance. About 260 instanced quetzal feathers (canvas texture with alpha, each with its own green from `instanceColor`) form a semicircle; inside are ring bands in gold, turquoise, pink, brown and turquoise, gold plates (instanced) and a gold frontlet. Its materials carry a `nightFactor` of 2.4–2.6, so at night they glow more strongly than by day; in addition `outdoor.penGlow` (three additive `glow` sprites in the penacho group — a large green and a gold aura behind the dark backing, which hides their centre so the light radiates round the feather tips, and a faint gold one in front) is shown only at night (`applyWeather`, included in `warmUp`). An info board (canvas texture with title, origin and the `ABOUT_WORKS` text, unlit `MeshBasicMaterial` so it reads in the dark room, on a dark wooden frame) hangs on the inner west wall between the front wall and the side door, facing into the room; like the proxy it is in `occluders` and `sculptureSpots` — clicks only find sculpture spots among the occluders. Nine torches stand on each balustrade of the main stair, from the foot up to the platform (`railTop` gives the balustrade's upper edge): wooden shaft and stone bowl merged per material, an additive flame sprite (canvas tongue) and an orange halo sprite. `updateTorches` makes them flicker from summed sines with a phase per torch; it runs as a turntable entry with `roof: true` and a sphere round the pyramid, so it only animates and forces renders while they are in view. `outdoor.torches.glow` (set in `applyWeather`: 1 at night, 0.55 in rain, 0.35 in sun) scales the halo. No real lights, which would cost every roof material. An invisible proxy in `sculptureSpots` opens the info panel; its texts are under „Federkopfschmuck des Moctezuma|Azteken, Mexiko, um 1515“ and `ABOUT_ARTISTS['Azteken']`. The room is walkable: `groundAt` gives `climb.floor` inside the temple footprint, and `climbBlocked` frees the room interior except the vitrine and a corridor through the middle of the front opening. All four stairways can be climbed: `climbSides` gives each side's outward distance and lateral offset, `groundAt` follows the step line from `climb.out` (stair foot) to `climb.h`, and `climbBlocked` leaves free only the stair corridors and the ring round the temple; terraces and balustrades block. It replaces the pyramid's box collider and is part of `isBlocked`, so A* finds the way up. The walk loop slides along the flanks and halves the speed on the stair, and eye height and `travelTo`/strolls follow `groundAt`. The stair slab and the top step are `climbMeshes`: clicking them walks there at their height; the other steps and the temple are `landBlockers`.
- **Weather** (`WEATHER`, `applyWeather`, button `#weatherToggle` next to ♪, kept in `localStorage` `wetter`): sun, moonlit night or rain. A switch only changes values — the sky canvas, the colour and intensity of sun and hemisphere light, the fog (`setOutdoorFog`; the fog colour equals the sky's horizon colour), the clouds' tint and opacity (`shade`), visibility (sun sprite, moon sprite, the 26 extra `rainOnly` clouds, the rain) and `emissiveIntensity`. It never swaps materials, so WebGPU recompiles nothing. Outdoor materials remember their emissive in `userData.baseEmissive` and are scaled by `emissive`. `userData.nightFactor` overrides the night factor (Colosseum floodlit, Burj offices lit), and `userData.nightGlow`/`glowI` give the villa windows and the Eiffel Tower a warm glow at night (mostly off otherwise). The moon sprite must start at the sun sprite's position: at the origin it sat in hall I and tinted it blue. The rain (`makeRain`, `updateRain`) is 3200 line segments in `roofGroup` at fixed world positions, wrapped round the camera, recomputed per frame only when it rains. `warmUp` briefly shows the rain, moon and rain clouds so their pipelines compile too.
- **Star sky** (night only, `drawStarSky` into the sky dome's canvas, 4096 × 2048 / 2048 on touch): the real sky over Vienna (`OBS_LAT`/`OBS_LON`), starting at the current sidereal time and turning as a time-lapse at `SKY_SPEED` (72×, one turn every 20 min; `skyNow`), with north at the pyramids (+Z) and west at +X. The stars live on their own sphere (`makeStarSphere`, `outdoor.stars`, child of the dome, radius `SKY_R` − 2, additive `MeshBasicNodeMaterial`): `drawStarSky` paints the whole sphere once at sidereal time `starsLst` (black background, no horizon culling), and `updateStarRotation` turns the sphere about the celestial pole `SKY_POLE` by the difference to the current sidereal time, five times a second while on the roof — the dome canvas itself only holds the gradient. Below the horizon the shader fades the stars out (`opacityNode`, smoothstep over the first ~7° of altitude). `skyLst` holds the current rotated sidereal time for clicking galaxies. `himmel/sterne.json` holds 5044 stars to magnitude 6 (colour from B−V, halo below magnitude 1.8), the Milky Way (rasterised once in equatorial coordinates, then reprojected pixel by pixel), the 110 Messier objects (galaxies, globular clusters, nebulae as soft spots) and the 88 constellations with lines and the three anchors of their figure. Sources: d3-celestial (BSD); lines and anchors from Stellarium's modern sky culture (CC BY-SA 4.0); figures `himmel/*.webp` by Johan Meuris/Stellarium (Free Art License), brightened ×2.1, drawn additively and warped onto the panorama as a 7 × 7 triangle mesh through a gnomonic tangent plane. The overlay's credits line names all three. Pixels follow `SphereGeometry`'s UV layout (`skyPx`). Seen from inside, the panorama is mirrored, so text must be drawn mirrored (`setTransform(-1/sinθ, …)`); everything placed by direction (stars, lines, triangle meshes) is correct. The buttons **✶ Linien** (lines plus names, galaxies labelled) and **✶ Figuren** appear only at night (`skyOpts`, `localStorage` `sternbilder`). Data and figures load lazily on first use (`loadSkyData`, `loadSkyArt`). `PSEUDO_CONS` adds an invented constellation, „Assange“ (a portrait with long hair, face, nose, mouth and collar, ~23° tall, centred at RA 112°, Dec +62° between Lynx and Camelopardalis, circumpolar over Vienna): points in degrees on a tangent plane, converted once to RA/Dec; its stars join the catalogue stars (`PSEUDO_STARS`) and its lines and name the ✶ Linien overlay (`PSEUDO_LINES`). `PSEUDO_ART` lays his portrait over it as a milky, translucent image: `himmel/assange-rot2.webp` (512 × 695) is David G Silvers' 2014 photo for Cancillería del Ecuador from Commons (CC BY-SA 2.0, credited on the start overlay), cut out with a hand-drawn polygon mask (eroded, feathered), greyscale, faded out towards the bottom, on black, tinted red throughout, with a red outline round head and shoulders (fading out below the neck, since the dark jacket merges with the background). It goes through the same three-anchor warp as the Stellarium figures (eyes and chin in image pixels → `eyeR`, `eyeL`, `chin`; the image's left eye goes to the east star, or the face would be mirrored), drawn additively at `alpha` 0.75, loaded lazily by `loadPseudoArt` and shown only with ✶ Figuren, like the other figures. While lines or figures are on, `skyObjectAt` also returns `'Assange'` for a click within 10.5° of the figure's centre (moon and galaxies take precedence); `SKY_PHOTOS.Assange` then shows the original photo in the lightbox, `skyTitle` names it „Julian Assange“. It has no figure image. At night the moon and the 40 Messier galaxies can be clicked (`skyObjectAt`: angle between the click ray and the object's direction at `skyLst`, the sidereal time of the last drawing; any building or wall in front blocks it). Hovering shows the name, a click opens the photo lightbox `#photo` (`showPhoto`, closed by click or Esc). The photos are listed in `SKY_PHOTOS`: 1280 px Commons thumbnails with author and licence, picked from the lead images of the English Wikipedia articles via the API. M32 and M65 were replaced, because one lead image was a negative and the other a comparison collage. German names are in `GALAXY_DE`. - **Look**: dragging rotates the camera using the "grab" metaphor — the scene follows the pointer, as in Street View or OrbitControls (`applyLook` *adds* the delta to yaw/pitch; an FPS scheme would subtract it). No Pointer Lock API, so the cursor stays free to click things.
- **Movement**: WASD/arrows feed `velFwd`/`velStrafe`, which are lerped toward the input each frame for smooth start/stop; the scroll wheel adds to `wheelVel`, an impulse that decays exponentially. Both are applied along the camera yaw in the render loop.
- **Click handling**: one `click` listener calls `handleSelect`, which resolves intent by raycast — a painting enters focus, the floor triggers `travelTo`, and anything else exits focus. `dragMoved` (set past `DRAG_THRESHOLD`) suppresses the click that ends a drag. Touch maps onto the same `pointerDown`/`pointerMove`/`pointerUp` helpers, with a tap calling `handleSelect`.
- **Focus mode**: `enterFocus`/`exitFocus` animate the camera to a frontal close-up of a painting, easing over a distance-scaled duration. Inside focus mode `focusState.zoom` runs from `ZOOM_MIN` (−1 = 4× magnification) through 0 (painting fills the screen) to 1 (painting plus placard), easing toward `zoomTarget`; the wheel, W/S (↑/↓) and a two-finger pinch set it. `focusPose` computes position and look point for any zoom and pan: above 0 the frame grows downward to `placardDrop` (painting centre → placard bottom, stored per hotspot); below 0 the distance shrinks by `4^zoom`. `focusState.pan` (metres from the painting centre) moves the look point across the painting; dragging sets it directly, and wheel/pinch adjust it in `zoomFocusAt` so the point under the cursor stays put. `focusPose` clamps pan so the view never leaves the painting — which also recentres it on zooming back out. Past roughly 1.5× (`zoomTarget < -0.3`) `showHiRes` upgrades to a 3840 px detail texture (`DETAIL_PX`). Commons only serves its standard thumbnail widths (… 1280, 1920, 3840); anything in between, e.g. 2560, returns HTTP 400. Portrait paintings therefore reach ~5800 px tall, within WebGPU's guaranteed 8192. A level is shown once it has loaded and is larger than the one on screen (`mesh.userData.shownPx`), so a failed load leaves the previous level in place, and nothing is downgraded within the same close-up. There is deliberately **no** distance limit on painting raycasts — clicking a painting several halls away walks you to it.
- **`travelTo`**: reuses the `focusState` animation machinery for click-to-walk, but leaves `focusState.active` false so normal movement resumes when it lands. `findPath` routes around obstacles: if the straight line is blocked (`navLineFree`, sampling `navFree` = `isBlocked` plus `roomIndexAt` on the ground floor), A* on a `NAV_CELL` (25 cm) grid over the current storey, no corner cutting, then string-pulled; an unreachable goal ends at the closest reachable cell. A detour (>2 points) is stored in `focusState.path` and followed by arc length (`pathPose`), the view turning smoothly into the walking direction; a straight walk keeps the view direction. Clicking a painting whose viewing point is behind a wall or plinth (`focusPainting`) walks there first and only then zooms in (`focusState.pendingSpot`). A click on the stair never pauses the climb, it resumes/continues in `stair.dir`; only W/S stop it.
- **Occlusion**: `occluders` collects wall meshes and joins the painting raycast, so a painting behind a wall is not clickable through it. Paintings sit ~0.02 in front of their wall, so their own wall never blocks them.
- **UI**: a start overlay with a loading bar (driven by `THREE.LoadingManager`; the start button stays dimmed until `onLoad` fires, since clicking before the module initializes does nothing), a room-name label that fades in/out on room transitions, a hover tooltip with title/artist, a **← Zurück** button shown only in focus mode, and an HUD hint whose text swaps between `HUD_DEFAULT` and `HUD_FOCUS`.
- **Esc**: exits the close-up first and only opens the menu when not focused.
- **Info panel** (`openInfo`, `ABOUT_WORKS`, `ABOUT_ARTISTS`): every picture and sculpture has a German text about the work and one about the artist (or, for prehistoric and Egyptian pieces, the origin). `ABOUT_WORKS` is keyed by `"title|artist"` exactly as in `ROOMS`/`DIVIDER_PAINTINGS`/`SCULPTURES`, `ABOUT_ARTISTS` by the artist line up to the first comma or " · " (`artistKey`) — keep both in sync when adding or renaming a work, or its ⓘ button stays hidden. Paintings open it via **ⓘ Über das Werk** in the close-up (switching paintings keeps it open with the new text); sculptures open it on click, their invisible proxies are in `sculptureSpots` and also give a hover tooltip. Esc closes the panel first. **Vorlesen** uses the browser's `speechSynthesis`: `bestVoice` ranks German voices (neural/"Natural" > Premium > enhanced/"erweitert" > Google/online, Apple's novelty voices excluded); local voices read a paragraph per utterance for natural phrasing, online ones a sentence each because Chrome cuts long online utterances after ~15 s. The music ducks to 0.05 while reading (`duckMusic`).
- **Music** (`makeJazz`, `scheduleBar`): quiet cool jazz synthesised live with Web Audio — no recordings, no vocals, nothing to download. An eight-bar II–V–I loop in C (`JAZZ_BARS`: bass root, rootless voicing, scale per bar) at `JAZZ_BPM`; FM electric piano with a random comping pattern per bar, walking bass with a chromatic approach to the next root, swung ride and brushes from filtered noise, and an occasional vibraphone phrase that moves stepwise. Everything runs through a generated-noise convolution reverb into a compressor; master gain fades in to 0.25 (≈ −27 dB RMS). The `AudioContext` is only created in `closeMenu` (browsers require a click), bars are scheduled 1 s ahead from a 120 ms interval, the context uses `latencyHint: 'playback'` and touch devices (`MOBILE_AUDIO`) get a 1.2 s instead of 2.4 s reverb — phones crackled otherwise while the GPU was busy, and the context is suspended while the tab is hidden, because background timers are throttled and would make it stutter. The **♪** button bottom right toggles it; the choice is kept in `localStorage` (`musik`).

## Languages (de, en, fr, it)

German is the source language and stays in `index.html` (titles, artist lines, `ABOUT_WORKS`, `ABOUT_ARTISTS`, UI copy). English, French and Italian live in `i18n/en.json`, `i18n/fr.json`, `i18n/it.json`, each `{ s, works, artists }`: `s` maps the **German string** to its translation (titles, artist lines, room names, UI texts, weather words, galaxy names), `works`/`artists` use the same keys as `ABOUT_WORKS`/`ABOUT_ARTISTS`. Anything missing falls back to German, so names and plain years need no entry. Whenever you add or rename a work, a UI string or an info text, add it to all three files.
- A classic script before the import map picks the language (`localStorage` `sprache`, else the browser language, else de), loads the dictionary early (`window.dictReady`, `window.I18N`) and translates every element with `data-i18n` (key: the element's German text without markup, whitespace collapsed; the translation may contain HTML) and `data-i18n-title`. It also draws the flag button and popup (`#lang`, top left, above the overlay; flags are inline SVG, since Windows shows no flag emoji). Choosing a language re-applies the DOM and fires the window event `sprache`.
- The module awaits `dictReady` before building. `tr(de)` translates; `setText`/`setTitle` store the German text on the element so a switch re-translates it (HUD, load text, room label, music/weather buttons, read-aloud button). Canvas texts are redrawn through `relabels` on `sprache`: placards (`makePlacardTexture`), hall signs (`makeSignTexture`), the penacho info board, the open info panel; the Burj clock uses the language's locale and reloads the place name. The spray label, sky titles and tooltips call `tr` when drawn. Read-aloud picks a voice of the current language (`SPEECH_LANG`).
- `sw.js` fetches `i18n/` network-first like the page.

## Installable app (PWA)

`manifest.webmanifest`, `sw.js`, `icons/`, `models/` (the sculpture GLBs), `bilder/` (the Maria stencil layers) and `himmel/` (star catalogue and constellation figures) sit next to `index.html` — the only exceptions to the single-file rule, since a service worker can't be inline. All paths are relative because the site lives under `/Museum3d/` on GitHub Pages. The start overlay has an **Als App installieren** button, driven by a small classic `<script>` right after the overlay markup, not the module, because `beforeinstallprompt` can fire before three.js has loaded. On Android and desktop Chromium it shows once that event arrives and opens the browser's own install dialog. iOS has no install API, so there the button only reveals the „Teilen → Zum Home-Bildschirm“ hint (iPadOS is detected via `MacIntel` + touch points). The button stays hidden when already running installed (`display-mode: standalone/fullscreen` or `navigator.standalone`). `sw.js` serves the page network-first with `cache: 'no-cache'` (GitHub Pages sends `max-age=600`, so a plain `fetch` could hand back the old page from the HTTP cache for ten minutes — updates didn't reach phones) and three.js from jsDelivr plus the Commons images cache-first, so the gallery works offline after one visit. Bump `CACHE` in `sw.js` when the caching strategy or the shell file list changes, **and whenever a same-origin file such as a model is replaced under the same name** — same-origin requests are cache-first too, so returning visitors would otherwise keep the old file. Better still, give a replaced model a new file name (as with `nofretete-berlin.glb`): the page that is already open still runs under the old worker, and new code with an old cached model breaks (e.g. sunglasses in mm floating beside the old 130-unit bust). The icons are a square crop of `docs/og-image.jpg` (Vermeer).

## Social preview

`<head>` carries Open Graph and Twitter Card tags pointing at `docs/og-image.jpg` (1200×630). Image URLs there **must stay absolute** — scrapers don't resolve relative paths. Regenerate the card by screenshotting the app with the HUD hidden and running `sips -c 784 1493 in.jpg --out crop.jpg && sips -z 630 1200 crop.jpg --out docs/og-image.jpg`. Scrapers cache aggressively; re-scrape via the platform's own debugger to see a change.

## Gotchas

- `requestAnimationFrame` is paused entirely while the tab is backgrounded, so camera animations do not advance and any in-page wait that polls for them will hang. When testing with browser automation, step the animation by taking screenshots rather than sleeping in the page.
- Placard textures are drawn to a fixed 1024px canvas; `makePlacardTexture` shrinks the font to fit, because long titles used to be clipped.

## Conventions

- Keep everything in `index.html` unless the file becomes unwieldy — this project is intentionally a zero-build single-file app.
- UI copy and code comments are in German, matching the existing content; keep new user-facing text consistent with that unless asked otherwise.
- Painting data uses Wikimedia Commons URLs — when adding artwork, prefer high-resolution Commons URLs and set `ratio` to the image's height/width.
- No shadows on painting images/frames beyond what's already there — don't add extra shadow effects to images (per user's global design preference).
