# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

A walkable 3D art museum rendered entirely client-side with Three.js. The whole app — markup, styles, and logic — lives in a single file: `index.html`. There is no build step, no package.json, and no bundler; Three.js is loaded from a CDN via an import map.

## Architecture (all in `index.html`)

- **Data**: `ROOMS` array defines five galleries on a grid: `cell: [col, row]` places each hall at `x = col·ROOM_W`, `z = row·ROOM_D`. Row 0 is the original enfilade (I Porträt, II Landschaft, III Moderne); IV Skulptur sits behind hall II (`[1, 1]`), V Gauguin in front of it (`[1, -1]`). Wherever two cells touch, a doorway appears automatically (`roomAt` lookups in `buildRoom`). Each hall lists its paintings per wall: `back` (z = ROOM_D) and `front` (z = 0) hold three, or only two when the wall has a doorway (a third is dropped silently); `left`/`right` hang two on a *closed* side wall (the former head-wall paintings now live in `ROOMS[0].left` and `ROOMS[2].right`). `DIVIDER_PAINTINGS` (keyed by the divider's world x, 16 or 32 — dividers only exist in row 0) hangs one painting per wall segment and side, `face: 1`/`-1` picking which of the two adjoining rooms it faces; Monet's *Impression* moved onto the back of the Whistler segment when hall II's back wall got its doorway. `bench` is optional — hall IV has none because `SCULPTURES` stand in its middle. Total: 41 pictures (40 paintings + a live-rendered Mandelbrot spiral) plus 2 sculptures; keep the meta description tags, the `og:`/`twitter:` variants, and the `Sammlung:` comment above `ROOMS` in sync if that changes. `roomIndexAt(x, z)` maps a world point to its hall (−1 outside).
- **Artwork URLs**: 1280px Commons thumbnails, not originals. Several originals are enormous (Starry Night is 44567×35291) and fifteen full-size textures would run to gigabytes of GPU memory. The data keeps the 1280px URLs, but `sizedUrl` rewrites the width when loading: every painting loads at 500px at startup (≈1.7 MB total instead of ≈11 MB), and only the painting in focus mode gets a 1920px texture (`showHiRes` in `enterFocus`). At most one high-res texture exists at a time; `dropHiRes` swaps back and disposes it once the exit animation finishes, not when it starts, so the picture doesn't visibly blur while the camera is still close. Only Commons' standard thumbnail widths (…, 500, 960, 1280, 1920, 3840) are safe to request; others return HTTP 400. When adding a work, get the URL and true `ratio` (height÷width) from the Commons API rather than guessing — and check `DateTimeOriginal`, since file titles often omit or misstate the year.
- **Scene setup**: standard Three.js scene/camera boilerplate, ACES tone mapping, fog for depth. The field of view is capped at 68° vertical *and* 80° horizontal (`applyFov`, also on resize): a fixed 68° vertical gave ~95° horizontally on a 16:10 window, and the edge stretch made the square marble tiles visibly grow and shrink while turning. The renderer is `WebGPURenderer` (import map points `three` at `three.webgpu.js`, r172), which falls back to its WebGL 2 backend on its own when `navigator.gpu` is missing — no separate code path. Its materials are converted to node materials internally; `onBeforeCompile`/`ShaderMaterial` tricks from the WebGL renderer won't work. No light casts shadows, so there's no shadow map.
- **Render on demand**: the scene is static, so the `setAnimationLoop` callback only calls `renderer.render` when the camera's world matrix changed or `needsRender` is set (texture loaded, resize, tab visible again). After any such change it keeps rendering for `SETTLE_FRAMES` (30) more frames, because a single frame after closing the start overlay sometimes stayed black. Resolution is capped by `MAX_PIXELS` (2.2 MP) in `applyRenderSize`, not just by `devicePixelRatio ≤ 2`: each pixel evaluates every light its hall sees, and a full-screen Retina Mac otherwise renders 4–5 MP versus ~1 MP on a phone — that's why the Mac ran slower than phones. Anything that changes the scene without moving the camera — e.g. a material change on hover — must set `needsRender = true` or it won't show until the next camera move.
- **Floor**: `makeMarbleFloorTexture` computes polished marble slabs pixel by pixel onto a 1024² canvas once at startup (~0.6 s on a Mac, behind the loading screen): 4 × 4 slabs of `MARBLE_SLAB_M` = 1 m per tile, a checkerboard of light Carrara and slightly greyer stone, each slab with its own value-noise turbulence driving a distorted sine for the veins (sharp core plus soft halo, so they don't read as cracks) and finer secondary veins. Because every slab has its own seed and the joints separate them, the noise never needs to tile — only the joint lines are split half/half across the tile edge. The floors get **world-space UVs** (`floorGeometry`: u = x / 4 m, v = −z / 4 m, no `texture.repeat`), so the pattern runs on seamlessly across all halls. Per-room UVs restarted the tile at each room's edge; halls IV and V (14 m = 3.5 tiles off hall II) were then shifted by half a tile, same-coloured slabs met at the doorway and read as double-size when crossing. `roughness: 0.28` lets the ceiling lights show as gloss on the floor. Each room's `floor` value is a near-white *tint* multiplied over the texture, not a solid color — dark values there would cancel the marble out.
- **Room construction** (`buildRoom`): builds floor, ceiling with light panels, front/back walls (two-tone: accent lower band, light upper band), side walls, and a genre sign above the entrance — on the front wall, except in halls behind the enfilade (row > 0), where it hangs on the back wall so it faces you as you enter. Front/back walls are single-sided planes, and each hall builds its own side of a shared one; with a doorway, `buildSolidWall` splits each band into pieces left and right of the opening plus one above `DOOR_H`. Jambs, lintel trim and colliders of a shared front/back wall are built only by the hall in front (via its back wall), mirroring the divider rule below.
- **Dividing walls** (`buildSideWall`): outer sides are a single plane; between two halls it builds a solid wall with a wide opening (`DOOR_W` × `DOOR_H`) — two box segments either side, a header above, and dark trim jambs. Boxes, not planes, because the wall is seen from both rooms. **The divider is built only by the left of the two halls** (`xLocal === ROOM_W`); both neighbours otherwise place identical geometry at the same world x, giving z-fighting and doubled colliders. `placePaintingOnSideWall` hangs paintings on these X-normal walls (`left`/`right` in `ROOMS`, and `DIVIDER_PAINTINGS`) — it's the X-axis counterpart to `placePainting`'s Z-normal logic, rotating the frame ±90° instead of 0°/180°. The standoff from the wall differs by geometry: `WALL_T + 0.02` off a flat plane (head wall, matching the front/back wall convention) vs. `WALL_T / 2 + 0.02` off a divider box's actual surface (half its own thickness, not the full plane convention — using the plane offset there would float the frame visibly off the box).
- **Painting construction** (`buildPainting`): fits each painting's texture into a bounding box preserving aspect ratio, adds a frame, a placard (rendered to a canvas texture), and two spotlights.
- **Painting lighting** — deliberately tuned, don't undo it casually: the canvas material is near-matte (`roughness: 0.98`) and carries the texture as an `emissiveMap` at `emissiveIntensity: 0.45`, so the artwork shows its true colors independent of the lights. Spots are narrow (32°) and dim (13) rather than floodlights. The earlier glossy material under a 42-intensity, 54° spot put a specular sheen over every painting and a white halo on the wall. Room brightness comes from the ceiling `PointLight`s, not the picture lights — raise those if a hall looks too dark, not the spots.
- **Light budget**: exactly **one** spot per painting, plus one per sculpture. The renderer is forward, so every light is evaluated per fragment. Scene total is 40 + 2 spots + 15 points + hemisphere + directional, but **no material sees all of them**: `assignRoomLights(root)` gives every `MeshStandardMaterial` under `root` a `lightsNode` (TSL `lights([...])`) with only the spot/point lights of the hall(s) its world bounding box touches (`roomsTouching`, both axes), plus hemisphere and directional. A hall's surfaces see roughly 10–14 lights; dividers, jambs and the shared front/back wall planes (which sit exactly on the boundary) see both halls. Shared materials get cloned once per hall set, each with its own `customProgramCacheKey`, because the renderer's shader cache treats every object-valued material property as `{}`. It runs once over the scene after building, and again on each sculpture model when its GLB arrives; anything else added later falls back to all lights. Mind this budget before adding more paintings, especially on mobile.
- **Mandelbrot spiral** (`makeMandelbrotTexture`, `updateMandelbrot`): a painting def with `procedural` instead of `url` gets that function's texture instead of a Commons image. The Mandelbrot one is a render target that a TSL `QuadMesh` fills with the fractal; the canvas itself is an ordinary painting material, so lighting matches the others. Deep zoom uses **perturbation theory**: `computeReference` iterates one reference orbit Z_n on the CPU in BigInt fixed point (`MANDEL_FP` = 160 fractional bits) and uploads it as a float `DataTexture` (`refTex`); the shader iterates only δ' = 2Zδ + δ² + δc in float32 and rebases (δ ← Z+δ, m ← 0) whenever |Z+δ| < |δ| or the reference ends, so one reference serves the whole view. The derivative is tracked per image width (`dzw`), not per unit c, or it overflows float32 deep down. The view (`mandel.cx/cy` as BigInt, `mandel.span`) changes only in the close-up: for a `fractal` hotspot the camera stops at zoom 0 (`focusPose` clamps), and negative zoom down to `MANDEL_ZOOM_MIN` (span 1e‑26, where δ would underflow) shrinks `span` instead; wheel/pinch keep the point under the cursor, dragging shifts the centre (`shiftMandelView`). Shift deltas go through `f2b`, which keeps the mantissa — a plain scale-and-round would lose them deep in the zoom. Each change renders a 640 px preview (`mandelLo`, ≤ `MANDEL_MAXIT_LO`); after `MANDEL_SETTLE_MS` the 1600 px version renders in `MANDEL_STRIPS` scissored strips, one per frame, with `autoClear` off after the first (a clear would wipe the whole target), so a 20 000-iteration pass can't stall the GPU long enough for a device reset. The last strip's scissor must stay inside the target or WebGPU drops it. Iterations grow with depth (`mandelIterations`, cap 20 000); areas needing more stay black. Leaving the close-up (`exitFocus`, `openMenu`, or switching paintings) resets the view. WGSL has no integer `mod()` in TSL r172 — the texel index is computed by hand.
- **Collision**: simple AABB colliders (`colliders` array) checked against a circular player radius in `resolveCollision`, which finally clamps the position into the nearest hall rectangle as a guard against tunnelling through a wall on a large step.
- **Sculptures** (`SCULPTURES`, `buildSculpture`): plinth, placard, glass vitrine (optional) and one spot are built synchronously; the model loads through `GLTFLoader` + `DRACOLoader` (decoder from jsDelivr) on the shared `loadingManager`, is scaled to `height`, stood on the plinth and turned by `rotY`. `models/david.glb` is the Scan-the-World STL from Commons (CC BY-SA 4.0), decimated to ~144k triangles without normals — `marble: true` recomputes vertex normals and swaps in a marble material. `models/tutanchamun.glb` is vmmaniac's Sketchfab model (CC BY 4.0, AI-reconstructed), resized with `gltf-transform optimize` (Draco, WebP textures at 1024 px); its gold gets the colour texture as an emissive map, since metal reads almost black without an environment map. An invisible proxy box per sculpture joins `occluders`, so paintings behind a statue aren't clickable through it without raycasting 100k+ triangles. The credits line on the start overlay fulfils the licences' attribution requirement — keep it.
- **Look**: dragging rotates the camera using the "grab" metaphor — the scene follows the pointer, as in Street View or OrbitControls (`applyLook` *adds* the delta to yaw/pitch; an FPS scheme would subtract it). No Pointer Lock API, so the cursor stays free to click things.
- **Movement**: WASD/arrows feed `velFwd`/`velStrafe`, which are lerped toward the input each frame for smooth start/stop; the scroll wheel adds to `wheelVel`, an impulse that decays exponentially. Both are applied along the camera yaw in the render loop.
- **Click handling**: one `click` listener calls `handleSelect`, which resolves intent by raycast — a painting enters focus, the floor triggers `travelTo`, and anything else exits focus. `dragMoved` (set past `DRAG_THRESHOLD`) suppresses the click that ends a drag. Touch maps onto the same `pointerDown`/`pointerMove`/`pointerUp` helpers, with a tap calling `handleSelect`.
- **Focus mode**: `enterFocus`/`exitFocus` animate the camera to a frontal close-up of a painting, easing over a distance-scaled duration. Inside focus mode `focusState.zoom` runs from `ZOOM_MIN` (−1 = 4× magnification) through 0 (painting fills the screen) to 1 (painting plus placard), easing toward `zoomTarget`; the wheel, W/S (↑/↓) and a two-finger pinch set it. `focusPose` computes position and look point for any zoom and pan: above 0 the frame grows downward to `placardDrop` (painting centre → placard bottom, stored per hotspot); below 0 the distance shrinks by `4^zoom`. `focusState.pan` (metres from the painting centre) moves the look point across the painting; dragging sets it directly, and wheel/pinch adjust it in `zoomFocusAt` so the point under the cursor stays put. `focusPose` clamps pan so the view never leaves the painting — which also recentres it on zooming back out. Past roughly 1.5× (`zoomTarget < -0.3`) `showHiRes` upgrades to a 3840 px detail texture (`DETAIL_PX`). Commons only serves its standard thumbnail widths (… 1280, 1920, 3840); anything in between, e.g. 2560, returns HTTP 400. Portrait paintings therefore reach ~5800 px tall, within WebGPU's guaranteed 8192. A level is shown once it has loaded and is larger than the one on screen (`mesh.userData.shownPx`), so a failed load leaves the previous level in place, and nothing is downgraded within the same close-up. There is deliberately **no** distance limit on painting raycasts — clicking a painting several halls away walks you to it.
- **`travelTo`**: reuses the same `focusState` animation machinery for click-to-walk, but leaves `focusState.active` false so normal movement resumes when it lands. It samples the straight-line path with `isBlocked` and stops short of a wall — the path runs at eye height, so a floor point visible through a doorway can still have a route that cuts through the wall beside it.
- **Occlusion**: `occluders` collects wall meshes and joins the painting raycast, so a painting behind a wall is not clickable through it. Paintings sit ~0.02 in front of their wall, so their own wall never blocks them.
- **UI**: a start overlay with a loading bar (driven by `THREE.LoadingManager`; the start button stays dimmed until `onLoad` fires, since clicking before the module initializes does nothing), a room-name label that fades in/out on room transitions, a hover tooltip with title/artist, a **← Zurück** button shown only in focus mode, and an HUD hint whose text swaps between `HUD_DEFAULT` and `HUD_FOCUS`.
- **Esc**: exits the close-up first and only opens the menu when not focused.

## Installable app (PWA)

`manifest.webmanifest`, `sw.js`, `icons/` and `models/` (the two sculpture GLBs) sit next to `index.html` — the only exceptions to the single-file rule, since a service worker can't be inline. All paths are relative because the site lives under `/Museum3d/` on GitHub Pages. The start overlay has an **Als App installieren** button, driven by a small classic `<script>` right after the overlay markup, not the module, because `beforeinstallprompt` can fire before three.js has loaded. On Android and desktop Chromium it shows once that event arrives and opens the browser's own install dialog. iOS has no install API, so there the button only reveals the „Teilen → Zum Home-Bildschirm“ hint (iPadOS is detected via `MacIntel` + touch points). The button stays hidden when already running installed (`display-mode: standalone/fullscreen` or `navigator.standalone`). `sw.js` serves the page network-first (updates show up immediately when online) and three.js from jsDelivr plus the Commons images cache-first, so the gallery works offline after one visit. Bump `CACHE` in `sw.js` when the caching strategy or the shell file list changes. The icons are a square crop of `docs/og-image.jpg` (Vermeer).

## Social preview

`<head>` carries Open Graph and Twitter Card tags pointing at `docs/og-image.jpg` (1200×630). Image URLs there **must stay absolute** — scrapers don't resolve relative paths. Regenerate the card by screenshotting the app with the HUD hidden and running `sips -c 784 1493 in.jpg --out crop.jpg && sips -z 630 1200 crop.jpg --out docs/og-image.jpg`. Scrapers cache aggressively; re-scrape via the platform's own debugger to see a change.

## Gotchas

- `requestAnimationFrame` is paused entirely while the tab is backgrounded, so camera animations do not advance and any in-page wait that polls for them will hang. When testing with browser automation, step the animation by taking screenshots rather than sleeping in the page.
- Placard textures are drawn to a fixed 1024px canvas; `makePlacardTexture` shrinks the font to fit, because long titles used to be clipped.

## Conventions

- Keep everything in `index.html` unless the file becomes unwieldy — this project is intentionally a zero-build single-file app.
- UI copy and code comments are in German, matching the existing content; keep new user-facing text consistent with that unless asked otherwise.
- Painting data uses Wikimedia Commons URLs — when adding artwork, prefer high-resolution Commons URLs and set `ratio` to the image's height/width.
- No shadows on painting images/frames beyond what's already there — don't add extra shadow effects to images (per user's global design preference).
