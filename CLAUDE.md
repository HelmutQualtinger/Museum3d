# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

A walkable 3D art museum rendered entirely client-side with Three.js. The whole app — markup, styles, and logic — lives in a single file: `index.html`. There is no build step, no package.json, and no bundler; Three.js is loaded from a CDN via an import map.

## Architecture (all in `index.html`)

- **Data**: `ROOMS` array defines three galleries (Portrait, Landscape, Modern), each with an accent color, floor tint, and **five** paintings (title, artist, image URL, aspect ratio) for the back/front walls. Order matters: the first three go on the back wall, the last two on the front wall — `buildRoom` slices by index, so adding a sixth entry silently does nothing until `BACK_X`/`FRONT_X` grow too. Two more data structures hang additional paintings on walls `ROOMS` doesn't cover: `HEAD_WALL_PAINTINGS` (keyed by room index 0 and 2 — the outer end walls at each end of the gallery run, two paintings each) and `DIVIDER_PAINTINGS` (keyed by the divider's world x, 16 or 32 — one painting per wall segment beside a doorway, `face: 1`/`-1` picking which of the two adjoining rooms it faces so the same physical wall shows different art on each side). Total painting count is 23; keep the meta description tags, the `og:`/`twitter:` variants, and the `Sammlung:` comment above `ROOMS` in sync with that number if it changes.
- **Artwork URLs**: 1280px Commons thumbnails, not originals. Several originals are enormous (Starry Night is 44567×35291) and fifteen full-size textures would run to gigabytes of GPU memory. The data keeps the 1280px URLs, but `sizedUrl` rewrites the width when loading: every painting loads at 500px at startup (≈1.7 MB total instead of ≈11 MB), and only the painting in focus mode gets a 1920px texture (`showHiRes` in `enterFocus`). At most one high-res texture exists at a time; `dropHiRes` swaps back and disposes it once the exit animation finishes, not when it starts, so the picture doesn't visibly blur while the camera is still close. Only Commons' standard thumbnail widths (…, 500, 960, 1280, 1920, …) are safe to request; other widths may be refused. When adding a work, get the URL and true `ratio` (height÷width) from the Commons API rather than guessing — and check `DateTimeOriginal`, since file titles often omit or misstate the year.
- **Scene setup**: standard Three.js scene/camera boilerplate, ACES tone mapping, fog for depth. The renderer is `WebGPURenderer` (import map points `three` at `three.webgpu.js`, r172), which falls back to its WebGL 2 backend on its own when `navigator.gpu` is missing — no separate code path. Its materials are converted to node materials internally; `onBeforeCompile`/`ShaderMaterial` tricks from the WebGL renderer won't work. No light casts shadows, so there's no shadow map.
- **Render on demand**: the scene is static, so the `setAnimationLoop` callback only calls `renderer.render` when the camera's world matrix changed or `needsRender` is set (texture loaded, resize, tab visible again). After any such change it keeps rendering for `SETTLE_FRAMES` (30) more frames, because a single frame after closing the start overlay sometimes stayed black. Resolution is capped by `MAX_PIXELS` (2.2 MP) in `applyRenderSize`, not just by `devicePixelRatio ≤ 2`: each pixel evaluates all 34 lights, and a full-screen Retina Mac otherwise renders 4–5 MP versus ~1 MP on a phone — that's why the Mac ran slower than phones. Anything that changes the scene without moving the camera — e.g. a material change on hover — must set `needsRender = true` or it won't show until the next camera move.
- **Floor**: `makeWoodFloorTexture` draws light oak planks onto a 1024² canvas once at startup (per-plank color variation, wavy grain, staggered butt joints, seams) and repeats the tile across every floor — one tile ≈ 3.5 m, so planks read about 35 cm wide. Grain strokes must return to their starting y at the tile's right edge or the repeat shows a seam. Each room's `floor` value is now a near-white *tint* multiplied over that texture, not a solid color — dark values there would cancel the planks out.
- **Room construction** (`buildRoom`): builds floor, ceiling with light panels, front/back walls (two-tone: accent lower band, light upper band), side walls, and a genre sign above the entrance.
- **Dividing walls** (`buildSideWall`): outer sides are a single plane; between two halls it builds a solid wall with a wide opening (`DOOR_W` × `DOOR_H`) — two box segments either side, a header above, and dark trim jambs. Boxes, not planes, because the wall is seen from both rooms. **The divider is built only by the left of the two halls** (`xLocal === ROOM_W`); both neighbours otherwise place identical geometry at the same world x, giving z-fighting and doubled colliders. `placePaintingOnSideWall` hangs paintings on these X-normal walls (`HEAD_WALL_PAINTINGS`/`DIVIDER_PAINTINGS`) — it's the X-axis counterpart to `placePainting`'s Z-normal logic, rotating the frame ±90° instead of 0°/180°. The standoff from the wall differs by geometry: `WALL_T + 0.02` off a flat plane (head wall, matching the front/back wall convention) vs. `WALL_T / 2 + 0.02` off a divider box's actual surface (half its own thickness, not the full plane convention — using the plane offset there would float the frame visibly off the box).
- **Painting construction** (`buildPainting`): fits each painting's texture into a bounding box preserving aspect ratio, adds a frame, a placard (rendered to a canvas texture), and two spotlights.
- **Painting lighting** — deliberately tuned, don't undo it casually: the canvas material is near-matte (`roughness: 0.98`) and carries the texture as an `emissiveMap` at `emissiveIntensity: 0.45`, so the artwork shows its true colors independent of the lights. Spots are narrow (32°) and dim (13) rather than floodlights. The earlier glossy material under a 42-intensity, 54° spot put a specular sheen over every painting and a white halo on the wall. Room brightness comes from the ceiling `PointLight`s, not the picture lights — raise those if a hall looks too dark, not the spots.
- **Light budget**: exactly **one** spot per painting. The renderer is forward, so every light is evaluated per fragment; two lights per painting at the current 23 would be 46 just from spots. A second, softer fill cone used to exist and was dropped — with an emissive canvas it barely registered, and the soft edge now comes from a higher `penumbra`. Scene total is 23 spots + 9 points + hemisphere + directional = 34, but **no material sees all of them**: `assignRoomLights` (run once after `buildRoom`) gives every `MeshStandardMaterial` a `lightsNode` (TSL `lights([...])`) with only the spot/point lights of the hall(s) its world-x bounding box touches, plus hemisphere and directional. A hall's surfaces see roughly 13 lights; divider boxes and jambs span two halls and see both. Shared materials (trim, ceiling …) get cloned once per hall set. Each clone also overrides `customProgramCacheKey`, because the renderer's shader cache treats every object-valued material property as `{}` and would otherwise hand one hall's shader, and lights, to another. Anything added to the scene after `assignRoomLights()` runs falls back to all lights. Mind this budget before adding more paintings, especially on mobile.
- **Collision**: simple AABB colliders (`colliders` array) checked against a circular player radius in `resolveCollision`.
- **Look**: dragging rotates the camera using the "grab" metaphor — the scene follows the pointer, as in Street View or OrbitControls (`applyLook` *adds* the delta to yaw/pitch; an FPS scheme would subtract it). No Pointer Lock API, so the cursor stays free to click things.
- **Movement**: WASD/arrows feed `velFwd`/`velStrafe`, which are lerped toward the input each frame for smooth start/stop; the scroll wheel adds to `wheelVel`, an impulse that decays exponentially. Both are applied along the camera yaw in the render loop.
- **Click handling**: one `click` listener calls `handleSelect`, which resolves intent by raycast — a painting enters focus, the floor triggers `travelTo`, and anything else exits focus. `dragMoved` (set past `DRAG_THRESHOLD`) suppresses the click that ends a drag. Touch maps onto the same `pointerDown`/`pointerMove`/`pointerUp` helpers, with a tap calling `handleSelect`.
- **Focus mode**: `enterFocus`/`exitFocus` animate the camera to a frontal close-up of a painting, easing over a distance-scaled duration. Inside focus mode `focusState.zoom` runs from `ZOOM_MIN` (−1 = 4× magnification) through 0 (painting fills the screen) to 1 (painting plus placard), easing toward `zoomTarget`; the wheel, W/S (↑/↓) and a two-finger pinch set it. `focusPose` computes position and look point for any zoom and pan: above 0 the frame grows downward to `placardDrop` (painting centre → placard bottom, stored per hotspot); below 0 the distance shrinks by `4^zoom`. `focusState.pan` (metres from the painting centre) moves the look point across the painting; dragging sets it directly, and wheel/pinch adjust it in `zoomFocusAt` so the point under the cursor stays put. `focusPose` clamps pan so the view never leaves the painting — which also recentres it on zooming back out. Past roughly 1.5× (`zoomTarget < -0.3`) `showHiRes` upgrades to a detail texture: 3840 px wide for landscape, 2560 px for portrait (`detailPx`), so the long side stays ≤ 4096, the texture limit of older phone GPUs. A larger level replaces a smaller one and is never downgraded within the same close-up. There is deliberately **no** distance limit on painting raycasts — clicking a painting several halls away walks you to it.
- **`travelTo`**: reuses the same `focusState` animation machinery for click-to-walk, but leaves `focusState.active` false so normal movement resumes when it lands. It samples the straight-line path with `isBlocked` and stops short of a wall — the path runs at eye height, so a floor point visible through a doorway can still have a route that cuts through the wall beside it.
- **Occlusion**: `occluders` collects wall meshes and joins the painting raycast, so a painting behind a wall is not clickable through it. Paintings sit ~0.02 in front of their wall, so their own wall never blocks them.
- **UI**: a start overlay with a loading bar (driven by `THREE.LoadingManager`; the start button stays dimmed until `onLoad` fires, since clicking before the module initializes does nothing), a room-name label that fades in/out on room transitions, a hover tooltip with title/artist, a **← Zurück** button shown only in focus mode, and an HUD hint whose text swaps between `HUD_DEFAULT` and `HUD_FOCUS`.
- **Esc**: exits the close-up first and only opens the menu when not focused.

## Installable app (PWA)

`manifest.webmanifest`, `sw.js` and `icons/` sit next to `index.html` — the only exceptions to the single-file rule, since a service worker can't be inline. All paths are relative because the site lives under `/Museum3d/` on GitHub Pages. `sw.js` serves the page network-first (updates show up immediately when online) and three.js from jsDelivr plus the Commons images cache-first, so the gallery works offline after one visit. Bump `CACHE` in `sw.js` when the caching strategy or the shell file list changes. The icons are a square crop of `docs/og-image.jpg` (Vermeer).

## Social preview

`<head>` carries Open Graph and Twitter Card tags pointing at `docs/og-image.jpg` (1200×630). Image URLs there **must stay absolute** — scrapers don't resolve relative paths. Regenerate the card by screenshotting the app with the HUD hidden and running `sips -c 784 1493 in.jpg --out crop.jpg && sips -z 630 1200 crop.jpg --out docs/og-image.jpg`. Scrapers cache aggressively; re-scrape via the platform's own debugger to see a change.

## Gotchas

- `requestAnimationFrame` is paused entirely while the tab is backgrounded, so camera animations do not advance and any in-page wait that polls for them will hang. When testing with browser automation, step the animation by taking screenshots rather than sleeping in the page.
- Placard textures are drawn to a fixed 1024px canvas; `makePlacardTexture` shrinks the font to fit, because long titles used to be clipped.

## Conventions

- Keep everything in `index.html` unless the file becomes unwieldy — this project is intentionally a zero-build single-file app.
- UI copy and code comments are in German, matching the existing content; keep new user-facing text consistent with that unless asked otherwise.
- Painting data uses Wikimedia Commons URLs — when adding artwork, prefer high-resolution Commons URLs and set `ratio` to the image's height/width.
- No shadows on painting images/frames beyond what's already there — don't add extra shadow effects to images (per user's global design preference).
